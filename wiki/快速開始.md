這份文件說明如何開始使用 LLM 知識庫系統。

## 基本概念

```
raw/     → 原始資料（只進不出）
wiki/    → 消化後的結構化筆記（LLM 維護）
AGENTS.md → 工作守則（本檔）
```

**核心流程：**
1. 把網頁/文章丟進 `raw/`
2. 告訴 agent「處理這個」
3. agent 在 `wiki/` 建立結構化筆記
4. 問 agent 問題，答案可以存回 wiki

---

## 方法一：Obsidian Web Clipper（推薦）

適合：部落格文章、新聞、知乎回答、Twitter/X 推文串

### 步驟 1：設定 Clipper（只需做一次）

1. 安裝 [Obsidian Web Clipper](https://obsidian.md/clipper) 擴充功能
2. 點擊擴充功能圖示 → 設定
3. 設定：
   - **Format**：Markdown
   - **Destination**：`C:/Cheerio/Obsidian/raw/`
   - **Filename**：`{{YYYY}}-{{MM}}-{{DD}}-{{Title}}`
   - 勾選「Download all images to vault」
   - **Images destination**：`C:/Cheerio/Obsidian/raw/assets/`

### 步驟 2：剪藏文章

1. 在瀏覽器看到想收藏的文章
2. 點擊 Clipper 圖示
3. 確認設定無誤，按「Save」
4. 回到 agent 說：「好了，這篇：https://example.com/article」

### 步驟 3：Agent 處理

```bash
好了，這篇：https://example.com/article
```

Agent 會：
1. 讀取 `raw/` 中的檔案
2. 與你討論重點
3. 在 `wiki/` 建立相關頁面
4. 更新 `wiki/index.md` 和 `wiki/log.md`

## 方法二：直接貼文字

適合：沒有瀏覽器的場景、純文字內容

直接把文字內容貼給 agent，格式不限（純文字、截圖描述、語音轉文字皆可）。

```bash
把這段話消化一下：
[你的文字內容]
```

---

## 方法三：放入 PDF/論文

適合：學術論文、技術報告

1. 把 PDF 放到 `raw/` 資料夾
2. 告訴 agent：「處理這個 PDF：`raw/xxx.pdf`」
3. Agent 會讀取並建立摘要

## 問問題

直接在對話中問：

```bash
問一下：[你的問題]
```

例如：
- 「問一下：Pi Agent 和 Claude Code 比起來有什麼優缺點？」
- 「問一下：Declaration Merging 在 TypeScript 裡怎麼用？」

Agent 會先查 wiki，再給出有引用來源的答案。

如果答案質量高，說「存到 wiki」就會建立新頁面。

## 定期維護

### Lint（健康檢查）

每累積 10 篇文章或每週一次，說：

```bash
lint wiki
```

Agent 會檢查：
- 矛盾資訊
- 過時內容
- 孤立頁面（沒有連結到其他頁面）
- 缺漏的交叉引用

## 常見問題

### Q: 為什麼不用 Notion 或其他工具？
A: 這個系統專為 LLM agent 設計。Notion API 需要付費，而 markdown + wiki 架構讓任何 LLM 都能直接讀寫。

### Q: 圖片怎麼處理？
A: Clipper 會自動下載圖片到 `raw/assets/`。在笔记中引用：`![[raw/assets/image.png]]`

### Q: 資料太多會變慢嗎？
A: 目前設計可以處理 ~100 來源、數百頁。未來可加搜尋引擎（見 AGENTS.md §6）。

### Q: 可以刪東西嗎？
A: 原則上不刪。但如果真的需要，告訴 agent「刪除 `wiki/xxx.md` 並更新 index」。
