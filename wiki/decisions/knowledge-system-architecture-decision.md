## 一、核心原則

### 我們的哲學
「任何認為對的事情都有可能會改變，有更好的方式可以做到，但我們想要的目標是不變的。」

### 目標（不變）
1. **知識幫助知識** — 查詢的結果能回填成新知識，形成正向循環
2. **看見關聯** — 透過 Obsidian 關聯檢視圖，發現以前忽略的交叉點
3. **突破創新成長** — 知識拓展不斷成長，幫助找到新的出口和機會

### 判斷標準
- 有效幫助目標 → 保留
- 無法幫助目標 → 改進（但需要足夠論點推翻）

### 2.1 目前的架構

```
┌─────────────────────────────────────────────────────────────┐
│  大腦 (wiki/)                                               │
│  ├── raw/        原始資料（只讀）                            │

│  │   ├── entities/     具體實作                              │

│  │   ├── decisions/    已確認選擇                            │
│  │   ├── discussions/  未定案方案                            │
│  │   ├── topics/       導航頁                                │
│  │   └── index.md      總覽                                  │
```

### 2.2 目前的問題

| 問題 | 對目標的影響 |
|------|--------------|

| Lint 只檢查結構 | ❌ 無法「突破創新成長」 |

## 三、解決方案

### 3.1 簡化後的架構

```
┌─────────────────────────────────────────────────────────────┐
│  三個操作 + 一個機制 + 一個回流                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  1. Ingest（吸收）                                   │   │
│  │     raw/ → 查詢既有知識 → 合成 → Staging → 寫入     │   │
│  └─────────────────────────────────────────────────────┘   │
│                            │                                │
│                            ▼                                │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  2. Query（查詢）                                    │   │
│  │     問問題 → 讀 index + 相關頁面 → 合成有引用回答    │   │
│  │     → 高價值洞察自動回 draft_backfill                │   │
│  └─────────────────────────────────────────────────────┘   │
│                            │                                │
│                            ▼                                │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  3. Lint（健康檢查）                                 │   │
│  │     掃描：結構 + 品質 + 半衰期 + 矛盾                │   │
│  │     → 人類確認後修復                                  │   │
│  └─────────────────────────────────────────────────────┘   │
│                            │                                │
│                            ▼                                │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  機制：知識幫助知識                                  │   │
│  │     Query 結果 → 品質評估 → Staging → 人類確認       │   │
│  │     → 正式知識                                       │   │
│  └─────────────────────────────────────────────────────┘   │
│                            │                                │
│                            ▼                                │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  回流：花園 → 大腦                                   │   │
│  │     種子成熟/研究專題新發現 → 觸發 Ingest            │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### 回流：花園 → 大腦

**目標：花園的價值能回流到大腦**

```
┌─────────────────────────────────────────────────────────┐
│  Notion 花園                                            │
│  ├── 種子成長為大樹                                     │
│  ├── 研究專題深入探索                                   │
│  └── 視覺地圖一目了然                                   │
└─────────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────┐
│  觸發條件                                               │
│  1. 種子狀態從 🌱 變為 🌳（成熟）                      │
│  2. 研究專題有新發現                                    │
│  3. 視覺地圖顯示新的關聯                                │
│  4. 人類主動說「這個值得深入研究」                      │
└─────────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────┐
│  花園 → 大腦                                            │
│  1. 自動抓取 Notion 頁面內容                            │
│  2. 建立 raw/notion-ingest/ 檔案                       │
│  3. 觸發 Ingest 流程                                   │
│  4. 進入 Staging Buffer → 人類確認 → 正式知識           │
└─────────────────────────────────────────────────────────┘
```

**關鍵原則：**
- **花園不只是展示層**：也可以是「靈感來源」
- **觸發條件**：種子成熟、研究專題新發現、人類主動
- **單向回流**：花園 → 大腦，不自動反向

### 3.2 各組件如何幫助目標

#### 組件1：Ingest（吸收）

**目標：讓所有資料都能被看見**

```
raw/（你的剪藏）
    │
    ▼
┌─────────────────────────────────────────────────────────┐
│  Ingest 流程                                            │
│  1. 讀取 raw 資料                                       │
│  2. 查詢既有 wiki（避免重複）                           │
│  3. 合成新知識（不篩選，只結構化）                      │
│  4. 寫入 Staging Buffer（安全隔離）                    │
│  5. 人類確認後寫入 wiki                                 │
└─────────────────────────────────────────────────────────┘
    │
    ▼
wiki/（結構化知識）
```

**關鍵原則：**
- **不篩選**：所有 raw 都會被消化，LLM 不能決定「什麼有價值」
- **先查詢再寫入**：避免重複，自動建立交叉引用
- **Staging Buffer**：安全隔離，防止幻覺污染
- **人類確認**：即使是 auto_verified，也需要人類確認後才能進入正式知識庫

#### 組件2：Query（查詢）

**目標：看見關聯，突破創新**

```
你的問題
    │
    ▼
┌─────────────────────────────────────────────────────────┐
│  Query 流程                                            │
│  1. 讀 index.md（快速找到相關頁面）                    │
│  2. 讀相關頁面（追溯交叉引用）                         │
│  3. 合成有引用的回答                                   │
│  4. 評估洞察品質（信心度 > 0.88?）                    │
│  5. 高價值洞察 → Staging Buffer                        │
│  6. 人類確認後 → 正式知識                               │
└─────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────┐
│  你的回答（有引用、有關聯、有新觀點）                   │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│  如果信心度 < 0.88：                                   │
│  → 告訴人類「我對這個回答不確定」                      │
│  → 說明不確定的原因                                    │
│  → 請人類決定是否要深入探索                            │
└─────────────────────────────────────────────────────────┘
```

**關鍵原則：**
- **先讀 index**：快速定位相關頁面
- **追溯交叉引用**：發現隱藏關聯
- **半自動回填**：自動暫存，但需要人類確認才能成為正式知識
- **不確定時要說**：信心度 < 0.88 時，要告訴人類為什麼不確定

#### 組件3：Lint（健康檢查）

**目標：確保知識品質，持續成長**

```
wiki/（結構化知識）
    │
    ▼
┌─────────────────────────────────────────────────────────┐
│  Lint 檢查項目                                         │
│  1. 結構完整性（frontmatter、provenance）              │
│  2. 孤立頁面（沒有 inbound links）                     │
│  3. 矛盾偵測（頁面間互相矛盾）                        │
│  4. 過時檢查（半衰期衰減）                             │
│  5. Source Fidelity（忠實原始來源）                    │
└─────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────┐
│  問題清單 → 人類確認後修復                              │
└─────────────────────────────────────────────────────────┘
```

**關鍵原則：**
- **不只檢查結構**：檢查知識品質
- **半衰期衰減**：自動標註過時內容
- **矛盾偵測**：主動發現衝突

#### 機制：知識幫助知識

**目標：查詢的結果能回填成新知識**

```
wiki-query 產出洞察
        │
        ▼
┌─────────────────────────────────────────────────────────┐
│  品質評估                                               │
│  信心度 S ≥ 0.88 → auto_verified                      │
│  0.70 ≤ S < 0.88 → draft_backfill                    │
│  S < 0.70 → 廢棄（但要告訴人類為什麼）                │
└─────────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────┐
│  Staging Buffer（暫存佇列）                            │
│  ├── TTL：21 天                                        │
│  └── 逾時自動清除                                      │
└─────────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────┐
│  人類確認 → 正式知識                                    │
└─────────────────────────────────────────────────────────┘
```

**關鍵原則：**
- **半自動**：自動暫存，但需要人類確認才能成為正式知識
- **Staging Buffer**：安全隔離，TTL 28 天
- **兩層分流**：簡單明確，易於實作

## 四、大腦結構的合理性

### 4.1 目前的大腦結構

```
wiki/
├── concepts/     抽象知識（可跨專案重用）
├── entities/     具體實作（人、工具、package）
├── sources/      來源筆記（整理後的外部資料）
├── decisions/    已確認選擇
├── discussions/  未定案方案
├── topics/       導航頁（只放導航，不放內容）
├── index.md      總覽（content-oriented）
└── log.md        時間日誌（chronological）
```

### 4.2 是否合理？

| 結構 | 是否合理 | 理由 |
|------|----------|------|
| **concepts/** | ✅ 合理 | 抽象知識可跨專案重用 |
| **entities/** | ✅ 合理 | 具體實作有明確邊界 |
| **sources/** | ✅ 合理 | 來源筆記保留 provenance |
| **decisions/** | ✅ 合理 | 已確認選擇有追溯價值 |
| **discussions/** | ✅ 合理 | 未定案方案保留探索空間 |
| **topics/** | ✅ 合理 | 導航頁幫助「看見關聯」 |
| **index.md** | ⚠️ 需加強 | 目前不完整，需要補強 |
| **log.md** | ⚠️ 需加強 | 目前不完整，需要補強 |

### 4.3 如何幫助「看見關聯」？

```
┌─────────────────────────────────────────────────────────────┐
│  Obsidian 關聯檢視圖                                       │
│                                                             │
│     ┌─────┐      ┌─────┐      ┌─────┐                     │
│     │concept│◄────►│entity│◄────►│source│                    │
│     └─────┘      └─────┘      └─────┘                     │
│         ▲              ▲              ▲                     │
│         │              │              │                     │
│         └──────────────┴──────────────┘                     │
│                    │                                        │
│                    ▼                                        │
│              ┌─────────┐                                   │
│              │  topic  │                                   │
│              └─────────┘                                   │
│                                                             │
│  每個頁面都用 [[wikilink]] 連結                             │
│  關聯檢視圖自動顯示所有關聯                                 │
│  發現以前忽略的交叉點                                       │
└─────────────────────────────────────────────────────────────┘
```

**關鍵：**
- 所有頁面都用 `[[wikilink]]` 連結
- 關聯檢視圖自動顯示所有關聯
- 發現以前忽略的交叉點和觀點

### 4.4 topics/ 是否會自動分裂？

**可以設計為半自動。**

```
目前的 topics/ 結構：
topics/
├── ai-agent.md
├── skill.md
├── knowledge-mgmt.md
└── ...

半自動分裂機制：
1. LLM 偵測到某個 topic 下頁面過多
2. LLM 建議分裂方案
3. 問人類：「是否要分裂這個 topic？」
4. 人類確認後才執行分裂
```

**關鍵原則：**
- **半自動**：LLM 建議，人類決定
- **有疑問時問人類**：模糊時不自動分裂
- **分裂前問人類**：不擅自分裂

## 五、花園的價值

### 5.1 花園如何幫助目標？

| 目標 | 花園的貢獻 |
|------|------------|
| **知識幫助知識** | 種子成長為大樹，知識不斷累積 |
| **看見關聯** | 視覺地圖一目了然，找到新的出口和機會 |
| **突破創新成長** | 研究專題幫助深入探索，視覺化幫助理解全局 |

### 5.2 花園跟大腦的關係

```
┌─────────────────────────────────────────────────────────────┐
│  大腦 (wiki/)                    花園 (Notion)              │
│  ┌─────────────┐                ┌─────────────┐            │
│  │ 結構化知識   │                │ 視覺化展示   │            │
│  │ (Markdown)  │◄───────────────│ (Notion)    │            │
│  └─────────────┘   單向回流      └─────────────┘            │
│         │                              │                    │
│         │      ┌─────────────┐        │                    │
│         └─────►│  單向同步   │        │                    │
│                │ wiki → Notion│        │                    │
│                └─────────────┘        │                    │
│                                                             │
│  大腦是 Single Source of Truth                              │
│  花園是視覺化展示層 + 靈感來源                             │
│  雙向流動：大腦 → 花園（同步）                             │
│             花園 → 大腦（回流）                             │
└─────────────────────────────────────────────────────────────┘
```

**關鍵：**
- 大腦是 Single Source of Truth
- 花園是視覺化展示層 + **靈感來源**
- **雙向流動**：大腦 → 花園（同步）+ 花園 → 大腦（回流）
- 回流需要觸發條件（種子成熟、研究專題新發現、人類主動）

```markdown
## 知識演化協定

### 權責分工
- 人類：sourcing、exploration、問好的問題、確認回填
- LLM：summarizing、cross-referencing、filing、bookkeeping

### 回填機制（半自動）
- Query 信心度 S ≥ 0.88 → auto_verified → Staging Buffer
- 0.70 ≤ S < 0.88 → draft_backfill → Staging Buffer
- S < 0.70 → 廢棄
- 所有回填都需要人類確認後才能成為正式知識

### 半衰期管理
- 快訊類：7 天
- 技術文件：180 天
- 歷史常識：3650 天

### 同步機制
- 大腦 → 花園：單向同步（wiki → Notion）
- 花園 → 大腦：單向回流（觸發條件：種子成熟、研究專題新發現、人類主動）

### Staging Buffer
- TTL：21 天
- 逾時自動清除
```

```markdown
### 知識品質檢查

1. **半衰期衰減**
```
