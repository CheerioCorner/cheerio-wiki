# 知識系統架構

> 經過 4 輪圓桌會議（Pi + Gemini + Copilot）討論後確定的知識管理系統架構。

## 一句話

三個操作（Ingest / Query / Lint）+ 一個機制（知識幫助知識）+ 一個回流（花園 → 大腦）。

## 核心原則

1. **知識幫助知識** — 查詢的結果能回填成新知識，形成正向循環
2. **看見關聯** — 透過 Obsidian 關聯檢視圖，發現以前忽略的交叉點
3. **突破創新成長** — 知識累積 + 視覺化，幫助找到新的出口和機會

## 架構圖

```
┌─────────────────────────────────────────────────────────────┐
│  三個操作 + 一個機制 + 一個回流                             │
├─────────────────────────────────────────────────────────────┤
│  1. Ingest：raw/ → 查詢 → 合成 → Staging → 人類確認 → 寫入 │
│  2. Query：問問題 → 讀 index → 合成有引用回答 → 回填        │
│  3. Lint：掃描結構 + 品質 + 半衰期 + 矛盾                   │
│  機制：知識幫助知識（Query → Staging → 人類確認 → 正式知識）│
│  回流：花園 → 大腦（種子成熟 → 觸發 Ingest）                │
└─────────────────────────────────────────────────────────────┘
```

## 各組件說明

### Ingest（吸收）

**目標：讓所有資料都能被看見**

- 讀取 raw 資料
- 查詢既有 wiki（避免重複）
- 合成新知識（不篩選，只結構化）
- 寫入 Staging Buffer（安全隔離）
- 人類確認後寫入 wiki

**關鍵原則：**
- 不篩選：所有 raw 都會被消化
- 先查詢再寫入：避免重複，自動建立交叉引用
- 人類確認：即使是 auto_verified，也需要人類確認

### Query（查詢）

**目標：看見關聯，突破創新**

- 讀 index.md（快速找到相關頁面）
- 讀相關頁面（追溯交叉引用）
- 合成有引用的回答
- 評估洞察品質（信心度 > 0.88?）
- 高價值洞察 → Staging Buffer
- 人類確認後 → 正式知識

**關鍵原則：**
- 先讀 index：快速定位相關頁面
- 追溯交叉引用：發現隱藏關聯
- 不確定時要說：信心度 < 0.88 時，要告訴人類為什麼不確定

### Lint（健康檢查）

**目標：確保知識品質，持續成長**

檢查項目：
1. 結構完整性（frontmatter、provenance）
2. 孤立頁面（沒有 inbound links）
3. 矛盾偵測（頁面間互相矛盾）
4. 過時檢查（半衰期衰減）
5. Source Fidelity（忠實原始來源）

### 機制：知識幫助知識

**目標：查詢的結果能回填成新知識**

- 信心度 S ≥ 0.88 → auto_verified → Staging Buffer
- 0.70 ≤ S < 0.88 → draft_backfill → Staging Buffer
- S < 0.70 → 廢棄（但要告訴人類為什麼）
- 所有回填都需要人類確認後才能成為正式知識

### 回流：花園 → 大腦

**目標：花園的價值能回流到大腦**

觸發條件：
1. 種子狀態從 🌱 變為 🌳（成熟）
2. 研究專題有新發現
3. 視覺地圖顯示新的關聯
4. 人類主動說「這個值得深入研究」
