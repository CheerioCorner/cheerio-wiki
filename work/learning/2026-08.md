### 2. 花園種植踩坑 + 修復

**做了什麼：**
- 用 `ntn pages create` 建了獨立內容頁
- 用 `ntn api v1/pages` 建了 Database 記錄
- 結果：兩個頁面，Database 記錄是空的

**問題與解決：**
| 問題 | 解法 | 預防措施 |
|------|------|----------|
| 建了兩個頁面 | 刪掉內容頁，把內容補到 Database 記錄 | 改 SKILL 流程 |
| Database 記錄沒有 body | 用 `ntn pages update` 補內容 | SKILL 裡明確標註 |

**學到什麼：**
- `ntn pages create --parent "page:..."` 建的是獨立頁面，不在 Database 裡
- `ntn api v1/pages -d '{"parent":{"database_id":"..."},...}'` 才是 Database 記錄
- Database 記錄的 body 要用 `ntn pages update` 另外補

**可以做得更好：**
- [x] 更新 knowledge-garden SKILL 修正流程
- [ ] 以後建 Database 記錄前先確認 parent 類型

## 模式觀察

### 今天觀察到的模式

1. **工具整合踩坑** — 新工具第一次用都會遇到 API 行為不符合預期
   - 例：Notion API 的 `pages create` vs `api v1/pages` 差異
   - 學到：先讀文件，不要假設行為

2. **SKILL 是好東西** — 把重複的流程寫成 SKILL 可以避免踩同樣的坑
   - 例：更新 knowledge-garden SKILL 後，以後不會再建出兩個頁面
   - 學到：踩坑後立即更新 SKILL

3. **視覺化溝通** — Annotator 比純文字更有效
   - 例：OCR 報告用 annotator 呈現，用戶可以標註
   - 學到：複雜資訊用視覺化工具
